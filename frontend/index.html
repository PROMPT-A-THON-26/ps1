User guide

Use VaultOps to inspect storage, upload objects, verify integrity, and operate recovery safely.

START HERE

Daily workflow

1. OverviewCheck the Part B connection, storage capacity, node health and active jobs.
2. ObjectsUpload a file or inspect an object. Details are loaded from the connected control plane.
3. IntegrityStart a checksum verification job and follow its durable status.
4. RepairsUse repair only when a committed version is under-replicated or a replica is unhealthy.
5. RebalanceMove a verified replica when capacity pressure or placement requires it.

TERMS

Simple language

ObjectA stored file and its version history
ReplicaA protected copy on a storage node
RF 3The configured replication factor is targeted
W2The configured write quorum must be met
HealthyStored data passed verification
CorruptedThe checksum does not match
RepairRebuild a missing or damaged replica
RebalanceMove a verified replica to improve placement or capacity

ABOUT THE PROJECT

About VaultOps

A user-facing control center for Vault's fault-tolerant distributed object storage system.

WHY IT EXISTS

Protect data through failure

VaultOps makes the distributed system visible: where objects are stored, how many healthy copies exist, which nodes need attention, and what the control plane is doing to recover from failure.

Storage layerStorage nodes
Control planeFastAPI + PostgreSQL + Celery
IntegritySHA-256 verification
Recovery ruleCopy → verify → commit → remove

PART BOUNDARY

Who owns what

Part AStores and transfers object bytes on storage nodes.
Part BOwns metadata, placement, health, integrity, repair, and rebalancing.
Part CExplains and operates those capabilities through this interface.

Operational numbers shown in VaultOps come from the connected control plane; the frontend does not fabricate cluster state.
